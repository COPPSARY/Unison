# Unison — agent rules

Unison is a Windows desktop app (Tauri 2 + React 19 + TypeScript) that plays music from local
files and from extensions (registries, packages and GitHub links), with local recommendations.
Spotify and YouTube were removed on 2026-11-20 (owner decision): extensions are the sources.
The full spec is the "AI Build Spec" doc; sections are referenced as §N.

## Workflow
- Read docs/PROGRESS.md first. Work on exactly one task (T-xx) from §11, in order.
- Before coding, write the task's acceptance criteria under "In progress".
- Finish with: pnpm lint && pnpm typecheck && pnpm test && cargo clippy -- -D warnings && cargo test
- Commit as feat(T-xx): summary. Update PROGRESS.md (Done / Blocked).
- Blocked or ambiguous? Write the question under "Blocked" and stop. Never guess API behaviour.

## Architecture rules
- All network calls happen in Rust. React only calls typed commands from src/lib/bindings.ts.
- Never edit src/lib/bindings.ts by hand; it is generated by tauri-specta.
- Secrets (extension credentials) live only in the OS keychain (keyring). Never in SQLite,
  logs, events, frontend state or crash reports.
- New music source = an extension, not built-in provider code. Extension logic lives in
  src-tauri/src/core/extensions; none in commands/ or the UI.
- Script extensions run only in the sandboxed QuickJS runtime (core/extensions/script): no file,
  process or module access; HTTP only to their declared hosts, checked on every redirect.
- No unwrap()/expect() outside tests. Errors are AppError with an ErrorCode (§9).
- SQL changes only through new files in src-tauri/migrations; never edit an applied migration.

## UI rules (Apple-inspired glass, dark-first — see docs/decisions/0002)
- Inspiration, not imitation: no SF Pro, SF Symbols, Apple logos or copied Apple Music layouts.
- Use role tokens from src/styles/tokens.css. No raw hex in components.
- Two layers: opaque content; glass only on the control/navigation layer (title bar, sidebar,
  player bar, menus, popovers, sheets, toasts) via the Glass primitives. Never glass-on-glass,
  never glass behind long text or table rows. Reduced transparency / "Off" => opaque.
- One accent (`--accent`, adapts to artwork, violet fallback) for primary action, selection,
  progress and focus only. Platform colours only inside source badges.
- Text uses label tiers (text, text-muted, text-tertiary, text-disabled); fills use fill tiers.
- Shapes: capsule buttons/segmented/search; concentric radii; cards 12px, floating panels 16-20px.
- Icons: lucide-react, 1.5px stroke, label colours. Never bright-coloured icons,
  never icons on tinted circles/squares (accent-filled play capsule is the exception).
  Sidebar nav icons are accent-tinted, Finder-style; selection there is a grey fill, no bar.
- Hover = tone change only. Press = scale 0.97 with the snappy spring. No lift/shadow on hover.
- Gradients only for: artwork ambient backdrop, glass rims, scrims, skeleton shimmer.
- Motion: springs from src/lib/spring.ts (smooth by default, snappy for press/popovers), opacity
  + small offsets/scale; nothing loops except shimmer; reduced motion => crossfade only.
- Type: Inter only (optical sizing, tracking via the type scale classes). Numbers tabular-nums,
  right-aligned. Spacing from the 4px scale only.
- No subtitles that repeat a title, no greeting banners, no emoji.
- Every data view has loading (skeleton), empty, no-results and error states.
- All user-facing strings in src/i18n/en.json.

## Commands
- Dev: pnpm tauri dev
- Seed demo data: pnpm seed
- Tests: pnpm test / cargo test (no live API calls; use tests/fixtures)
- Build installer: pnpm tauri build

## Never
- Commit .env.local, keys, tokens or fixture files containing real user data.
- Add ad-blocking, or audio download beyond docs/decisions/0005: only sources with an open
  licence (Creative Commons, CC0, public domain) through core/extensions/download.rs; never call
  an extension's download(); scripts get no file / ffmpeg APIs.
- Add features not marked "In" in §2; put ideas in docs/IDEAS.md.

## Universal player (see docs/Unison-Universal-Player.pdf, §UP)
- Work order: UP-01..UP-16 after T-15, then T-16. T-40..T-44 are replaced by UP tasks.
- Rust owns the queue, resolver and all engines' state. The UI never decides which source plays.
- Engine: NativeEngine (local files, Audius and extension HTTP streams, symphonia + rodio/cpal).
- Stream extension audio in memory; the only thing written to disk is an open-licence download
  (docs/decisions/0005), which becomes the song's local file.
- Fallback may only switch between sources merged into the same tracks row. Never play a
  different song as a substitute. Audius merges only on ISRC or strict match (0.95/0.95/±2s).
- Local files are referenced in place by default; fingerprint = size + BLAKE3(first 1MB + last 64KB).
  Never modify the user's audio files or tags.
- Imports and folder scans run in background tasks with progress events; never block a command
  for more than 200ms.
- Audius API key lives in the keychain (audius.api_key). Credit the artist wherever an Audius track shows.
- Every fallback writes a playback_log row with ended_reason = 'fallback' and emits player://fallback.
- Numbering in this repo: the addendum's migration '0002_universal_player.sql' is
  '0003_universal_player.sql' (0002 already applied) and its 'ADR 0002' is docs/decisions/0004.
